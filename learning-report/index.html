4 · 顺手在项目里搞懂直播

FLV vs HLS：一条靠拆包换装，一条靠切片列表

做直播播放器时把两条流协议的原理弄懂了。FLV 靠 HTTP 长连接持续推 Tag 字节流，浏览器不认这格式，全靠 flv.js 把 Tag 拆出 H.264/AAC 帧、重封装成 fMP4 塞进 MSE，随到随播、延迟 1~3s；HLS 是「m3u8 清单 + 2~10s 分片」，播放器每几秒轮询一次清单、发现新分片就下载按序播，延迟 10~30s，但分片是静态文件，全端兼容、随便走 CDN。

怎么选：要实时（监控、对讲、内网）走 FLV；要兼容和分发（公网、手机、点播）走 HLS。对应项目里就是两套播放器并存——FlvPlayer.vue（flv.js）扛低延迟，VideoPlayer.vue（EasyPlayer）兜底 iPhone 和 RTSP/HLS。
5 · 在项目里搞懂 Vue hooks

核心收获：用 hook 复用一个业务的通用逻辑，重点是 usePageListHook

Vue 逻辑复用从全写进页面 → mixins → hooks 一路演进，项目正处在 mixins → hooks 迁移中途（老页面走 mixins，审批模块走 hooks）。这轮最大的收获不是学会了 hooks 语法，而是想明白了一件事：可以把一个业务里反复要写的逻辑抽成一个 hook，页面传个参数就能用。最典型的就是 usePageListHook——以前每个列表页都要自己写一遍查询参数、分页、loading、勾选、删除确认，现在全收进这个 hook 里，页面只传个 getListApi 就行。

usePageListHook 在用 · 重点
把列表页反复要写的逻辑抽成 hook：查询参数、分页、loading、勾选跨页回显、删除确认，全由这个 hook 管着。
页面只需要传 getListApi（必传）；hook 返回 list、pagination、loadingList、search、getList、resetQuery、selectedRecords、confirm；表格和容器的 ref 名约定好用 tableRef 和 tableWrapperRef。
useTableHeight 在用
按容器算表格高度，fixHeight 补偿（36/40/60 各页不同），resizeTable 手动重算。
useDialogHook 备用
弹窗表单的一整套逻辑：传 form 和 formRef 进去，跟 mixins 版的 dialog.js 是一回事。
useButtonPermissionHook 备用
hasButtonPermission('菜单code:按钮code')，三级判断（开关 → 超管 → auths Map），等价 button-permission.js。
一句话现状：usePageListHook + useTableHeight 是审批模块在用的新方案；useDialogHook、useButtonPermissionHook 逻辑已写好但业务仍走等价 mixins 版，处于迁移中途。
02

做出来的东西，都是干什么用的

api-rules Skill
管后端接口怎么写的一套规矩，AI 写代码时自动套用。

起因是想统一前端和后端的代码风格，让前端拿到的数据跟后端接口对得上。这套规范定了：成功只返回 {data}，出错返回 {error:{code,message}}，分页才加 meta；错误码用字符串（比如 INVALID_PASSWORD）而不是数字；URL 统一走 /api/v1/；时间用 ISO 8601；token 放 Authorization 头。

还写清楚了 DTO 什么时候该建、什么时候可以省，公共类型必须放 common 模块不许各模块各抄一份。

例子：密码错了 → HTTP 401 + {error:{code:"INVALID_PASSWORD", message:"邮箱或密码错误"}}；列表接口 → {data:[...], meta:{page:1, pageSize:20, total:200}}。

moni-app-skill Skill
Android 写界面的规范，Kotlin + Compose + MVVM。

强制每个页面拆成 Screen / ViewModel / UiState 三个文件，ViewModel 里不许碰 View；颜色、字号、间距不许写死，全部走主题。用户说「加个登录页」，就只生成这三件套，不多加没用的文件。

还特意写了个 scan_logging_utils.js 脚本：写日志之前先扫一遍项目有没有自己的日志工具，有就跟着用，没有就别硬塞 android.util.Log——避免往别人的项目里乱加东西。

这套脚本自己配了单元测试（test_scan_logging_utils.js），属于「工具 + 验证」都做齐了。

profession-commentor Skill
Java 代码怎么写注释的规矩，用中文。

核心就一句话：代码讲「做了什么」，注释讲「为什么这么做」。类和方法要写 Javadoc（带 @author moni），方法写清楚参数、返回值、可能抛的异常，DTO 的每个字段都要说明。

反过来，字段名一看就懂的就别注释；「// 创建用户」这种废话注释被当成反面教材写进了规范里。

例子：注释「按创建时间倒序排序，让最新日记显示在最前面」可以；注释「对日记进行排序」不行。

writeself_app_style_rules Skill
WriteSelf 这个 App 的设计规范，体量最大的一件。

拆成 6 个文件各管一摊：颜色体系、组件样式、页面怎么排、什么信息该用什么组件展示、跨页间距、总规则。AI 生成界面最爱犯的毛病全列了——时间戳被包成 Chip、卡片带阴影、主按钮用纯色、错误提示用灰字弱化、登录页做成双栏仪表盘……

规范给了 9 步检查流程，每步指向具体规则文件的章节，改完哪一条都查得到依据；规则文件之间打架时（比如总规则说卡片可以有柔阴影，组件规则说先不做），明确以更细的组件规则为准。另配 15 个「错误写法 → 正确写法」案例。

例子：主按钮必须用 #B18BFC→#8F7AE5 的水平渐变，纯色直接判违规；时间戳、天气这类信息必须是纯文字，套 Chip 算违规。

monideui Agent
一个「UI 视觉设计师」智能体——把 BMAD 立人设的做法复刻了一遍。

customize.toml 里给它立了个人设：以 Dieter Rams 和 Don Norman 的设计观为原型，极简、克制、以用户为中心。用户找它做界面时，它会先走 8 步激活流程，再按页面设计风格分发任务——目前按 WriteSelf 风格出设计时调 writeself-app-style-rules 技能，后续可以扩展成不同设计风格调用不同的 skill。
