# 桌面宠物生成 Skill

> 通用原则：**输入参数化、流程分支化、实现参考化、验收可配置化**。
> 具体项目、具体角色、具体帧序列、具体技术栈都只是"默认示例/参考实现"，一律放 `references/`，不写进主流程当规范。
> 主文件及 references 中的具体数值/帧序列/代码片段，**除非明确标注为规范，否则一律视为示例**，使用前按当前角色、平台、技术栈重新确认，禁止原样照抄；"透明 PNG、无阴影"这类硬性要求属于规范，不属示例。

## 0. 默认与覆盖

默认配置：**Electron + Windows + Q 版 + 呼吸浮动待机 + 帧动画交互**。
所有默认项都可以被用户需求覆盖；用户未明确时用默认值，并在交付说明中标注假设。

## 1. 需求收集（必做）

开始产出前先确认以下条目（用 question 工具一次性收集，避免逐项追问）：

- **平台**：Windows / macOS / Linux
- **技术栈**：Electron / Tauri / PyQt / WebView / 其他
- **角色风格**：Q版 / 像素 / 写实 / 用户自带素材（**3D 暂不实现**）
- **参考素材**：有参考图（用户提供）/ 无参考图（先提醒，或按 §4 规则确认是否随机生成一版看效果）
- **方向数**：1 / 4 / 8 / 自定义
- **待机动画**（可多选，创建时必问）：无动画 / 呼吸浮动（默认）/ 随机张望 / 躺卧休息 / 循环小动作（眨眼/摇摆/伸懒腰…）/ 随机混合（多种随机触发）
- **动画方式**：程序化 / 帧动画 / 骨骼 / Live2D / Spine
- **交互**（可多选）：拖拽 / 双击 / 右键菜单 / 窗口跟随 / 点击穿透 / 多宠
- **交付形态**：开发运行 / 绿色免安装 / 安装包

> **兜底规则**（防止输入不全/中途变更导致流程卡死）：
> - 某条目用户未回答 → 直接用默认值（见 §0），并在交付说明中列出"采用假设"清单；
> - 用户说"你定/随便" → 不再追问，直接使用默认组合；
> - **中途改需求** → 优先只改 `pet.config.json` 与资产；**若涉及技术栈/平台变更，窗口层与打包层同步重构**；已生成资产按变更重新生成并标注，已交付项保持可回滚；
> - 需求无法满足（如平台不支持透明窗口）→ 先告知影响与替代方案，由用户决定，不擅自降级。

## 3. 通用架构

任何桌宠 = **透明置顶窗口 + 资产包 + 配置文件 + 状态机 + 交互层 + 渲染层**。

> 下面是**产出项目**的目录结构；`references/` 是本 skill 自带的参考文档目录，**不属于产出项目，不要复制进去**。

```
desktop-pet/
├── pet.config.json   # 唯一事实源：资产映射、方向、动画、交互、窗口
├── images/           # 2D 贴图
├── src/              # 渲染/动画逻辑（只读配置，不写死任何方向/帧序列）
├── main/             # 窗口层（按技术栈实现）
└── (打包产物由打包层产出)
```

## 4. 角色资产生产

> **参考图规则（必做，先于产图）**：
> - 用户**有参考图** → 基于参考图精调锚点资产；
> - 用户**没有参考图** → **先提醒用户提供参考图**（保证形象一致）；若用户表示没有或无所谓，**询问是否先随便生成一版看看效果**（用通用描述生成锚点图给用户确认形象），用户确认后再进入精调；
> - **确认参考图来源后，追问下一步走向**（用 question 一次性问，三选一）：
>   1. **先搭建项目骨架** → 形象未定不影响窗口层/配置驱动框架，先建项目结构，产图等参考图到位再回到本节；
>   2. **等待用户生成参考图** → 暂停产图相关步骤，用户拿到参考图后再继续；
>   3. **已有参考图，马上发** → **立即中断当前流程/对话**，停住等用户发图，收到参考图再继续后续步骤，期间不推进其他工作；
> - 未取得用户确认前，不批量生成全套方向/动作图，避免返工。

> **风格分支**：2D 风格（Q版/像素/写实）走本节贴图流程；**3D 风格暂不实现**（相关方案存档于 `references/3d.md`，未来恢复时再启用）。

### 4.1 资产规格说明书（先出配置，再产图）

先用 `pet.config.json` 的 `character` 段写清规格，用户确认后再开始生成图片：

```json
{
  "character": {
    "style": "chibi",
    "description": "红色无袖毛衣 + 黑色长直发，细长上挑眼，深棕瞳",
    "directions": ["front", "back", "left", "right"],
    "scaleMap": { "front": 1.0, "sitting": 0.82 },
    "assets": {
      "idle": { "front": "images/front.png" },
      "jump": { "frames": ["images/jump_1.png", "images/jump_2.png"] }
    }
  }
}
```

每张图的统一要求：**透明背景 PNG、无地面阴影、无投影、无 AI 生成水印残留、指定视角、人物占比一致**。
命名规则：`方向/动作.png`，与 `assets` 映射一一对应；斜向方向名用 `front_left` 这类语义名。

> 上述 JSON 与命名都是**示例**：`directions`/`scaleMap` 数值/`assets` 映射均按角色实际替换，**可改可省**（如 1 方向项目可省去 `back/left/right`）。

### 4.2 生成 / 抠图 / 命名

- **生成**：任意图像生成工具均可；以"先精调确认**锚点资产**"为基准，其余方向/姿势基于它生成，保证形象一致（锚点按风格选：Q版=正面图 / 像素=基准 sprite / Live2D=基准表情）。
- **抠图**：任意抠图工具，**只要求输出透明 PNG**。示例工具与命令见 `references/asset-generation.md`。
- **校验**：边缘干净、无残留背景、底部无残影、**无 AI 生成水印残留（底部/角落文字标记，需像素级检查确认，避免视觉模型误判人物本体）**、人物在画布中占比统一（用 scaleMap 兜底微调）。

> **水印清除流程（规范，先于裁剪缩放）**：
> 0. **先定性水印位置**：生成工具通常把"AI生成"等文字标记叠加在**画面右下角**，浅灰/白色文字、**可能是半透明**。裁剪缩放前先确认它压背景还是压人物，再选清理路径。
> 1. **优先用留白法从源头规避（推荐，用户环境验证）**：生成时在画面下方预留一片**空白**，水印会自动落在空白区，裁掉该空白即可，干净无擦除。**注意坑**：部分生图模型在"底部留白"构图下会**拒绝某些姿势**（实测：要求留白+歪头时，连续 6 次歪头角度=0°）。姿势与留白无法兼得时，改用"正常姿势生成 + 事后擦除右下角"（见 2-7）。
> 2. **事后擦除：程序化扫描水印真实范围**：对右下区域做像素统计，找"中灰~浅灰、接近中性色"的聚集像素，取其 bbox 作水印区，**范围宁大勿小**（实测清到 x≥0.85、y≥0.84 才干净，远超"右下角"的直觉）。
> 3. **半透明必须清**：水印常是**半透明**（alpha 只有几十）。**只按不透明像素（alpha>120）扫描会漏掉整块**，务必按 `alpha>0 且 中性浅灰` 来识别与清除。
> 4. **背景用"连通域从边界提取"，勿整块矩形填白**：从四边向内做连通域标记，把**触及图像边界**的浅色中性区整片判为背景（用 `scipy.ndimage.label`；**PIL `ImageDraw.floodfill` 有静默返回 0、背景没清掉的坑**）。人物肢体可能伸进水印区，整块矩形填白会切掉人物，只对"中性浅灰"像素操作。
> 5. **勿用高斯模糊给 alpha 羽化**：会沿角色边缘产生**半透明伪影**，既像水印残留又造成误判；需要平滑就做阈值截断/重设 alpha，不要模糊 alpha。
> 6. **成品双向复核**：裁剪缩放后，按 `alpha>0 且 中性浅灰` 重扫底部/四角，**成片条带=没清干净**；零星 1-2px 低 alpha 边缘像素属正常。同时黑/深红底 4~10 倍 **NEAREST** 放大肉眼查看（不要用柔化缩放，会掩盖/伪造痕迹）。
> 7. **最终复核与落盘**：视觉模型对水印判断不可靠（漏判真水印、误报反光），**以像素级扫描为准、视觉仅作补充**。拷进目标目录后**重新读回磁盘文件**核对（MD5/尺寸 + 水区再扫），防被外部会话/同步覆盖成带水印版。

### 4.3 方向与动作按需，不固定八方向

- 只做待机 → **1 方向 + 左右翻转**即可；
- 做拖拽方向切换 → **4 或 8 方向**；
- 动作（跳跃/睡觉/眨眼…）按角色需要**按需扩展**，帧序列、姿势数量不写死。

> **待机动画与资产对应**（按 §1 选择的待机动画生成对应资产）：
> - **无动画** → 仅 `front` 一张即可，无额外资产；
> - **呼吸浮动** → 纯程序化（呼吸缩放+上下浮动），**不需要额外贴图**；
> - **随机张望** → 需要侧面/斜向贴图（`left/right` 或 `front_left/right`），或基于 1 方向镜像；
> - **躺卧休息** → 需要 `lying`（躺卧）贴图，可叠加呼吸缩放；
> - **循环小动作**（眨眼/摇摆/伸懒腰…）→ 每个小动作一组关键帧序列（如 `blink_1/blink_2`）；
> - **随机混合** → 多个待机动作循环随机触发，资产为上述各选项之和，代码里按权重随机。
>
> **每种待机模式的完整规则（资产/参数表/实现/错误处理/交付标准）见 `references/idle.md` 单文件（§0 模式速查 + §2 通用规范 + 所选模式一节），选定模式后按该文件执行与验收。**

## 5. 实现层

### 5.1 窗口层

透明、无边框、置顶、隐藏任务栏。具体参数与代码按技术栈查：
`references/electron.md` / `references/tauri.md` / `references/pyqt.md`。

> 需要一份**完整可运行**的参考实现（含主/渲染进程全部关键代码）时，直接看 `references/example-electron.md`。

### 5.2 渲染层（配置驱动）

渲染逻辑**只读 pet.config.json**，自动推导，不手写死表：

- 方向列表 = 配置的 `directions`；
- **降级链自动推导（默认规则）**：缺 `left` → 用 `right` 水平镜像；缺斜向 → 回退到最近的轴向（`front_left` → `left` 或 `front`）；缺 `back` → `front`；最终兜底 `front`。以上可在 `pet.config.json` 的 `fallback` 段显式覆盖；**非对称角色（单边疤痕/发型/眼罩）必须显式指定降级**，不能依赖镜像；
- 缩放表 = 配置的 `scaleMap`（保证不同姿势人物视觉大小一致）。

### 5.3 交互层

按启用的能力挂接，不默认全开：

- **拖拽**：用"鼠标位移增量"移动窗口（比系统拖拽区更流畅，可同时切贴图），技术栈相关实现见 references；
- **双击 / 右键 / 点击特效 / 窗口跟随**：可选能力，按需求启用；
- **窗口跟随**：平台相关，见 `references/follow-window-pitfalls.md`（核心是"只跟随新窗口 + 冷却 + 防抖"）。

### 5.4 状态机与动画

- 用互斥状态位（命名按启用能力自定，如 `isDragging / isJumping / isSitting ...`）+ 定时器管理，避免并发冲突；
- 动画可混合：程序化（呼吸/浮动/跳跃抛物线）与帧动画（关键帧序列）可同用；
- **待机动画（idle）**：按 §1 选择的待机选项实现，写入 `pet.config.json` 的 `idle` 段（`mode` + 参数/帧引用），状态机进入 idle 时按配置播放；默认 `呼吸浮动`（程序化，无需资产）；完整规则见 `references/idle.md`；
- 动画方式选型参考 `references/animation.md`（骨骼/Live2D 属 2D 表现，正常可用）。

## 7. 验收清单（必做 / 按需）

> **未启用能力不产代码**：下列「按需」项在 §1 需求收集未启用时，一律不实现、不参与验收；验收只覆盖实际启用的能力。

### 必做（所有桌宠）

- [ ] 窗口：透明、无边框、置顶、不进任务栏（按平台能力）
- [ ] 贴图：透明 PNG、无阴影、人物大小统一
- [ ] 配置驱动：方向列表/降级链/缩放表来自 `pet.config.json`，代码无硬编码
- [ ] 基础运行：启动不报错、无未捕获异常、日志可排查

### 按需启用（仅在需求收集启用时验收）

- [ ] 拖拽：顺滑、方向切换正确、松手恢复
- [ ] 双击 / 右键：动作正确、开关生效
- [ ] 窗口跟随：只对新窗口移动、不追鼠标
- [ ] 单实例：重复启动聚焦已有
- [ ] 动画：帧数流畅、无闪烁、状态互斥无冲突
- [ ] 待机动画：按 §1 选择的待机选项正确运行（呼吸浮动/张望/躺卧/循环小动作/随机混合），资产与配置对应
- [ ] 打包产物：对应平台可运行
