## 1. 与 2D 流程的差异（读本文前先看这张表）

| 环节 | 主流程（2D 贴图） | 本文（3D 模型） |
|---|---|---|
| 资产 | 透明 PNG 贴图（抠图/八方向） | 3D 模型（glTF/GLB）+ 动画 clip |
| 方向表现 | 多方向贴图切换 | 模型朝向（yaw 旋转）或相机环绕 |
| 待机 | 呼吸/浮动（程序化） | idle 动画循环 + 程序化呼吸叠加 |
| 缺失降级 | 镜像/翻转/兜底 front | 缺动画 clip → 换其他 clip 或程序化替代 |
| 抠图 | 必须 | **不需要**（透明由渲染器产生） |
| 人物大小统一 | scaleMap 缩放贴图 | 模型归一化（包围盒对齐） |

## 2. 技术栈

- **Electron + three.js（推荐）**：透明置顶窗口直接复用 `electron.md`，渲染层用 three.js 加载模型；后端代码面最小。
- **Tauri + three.js**：同上，体积更小。
- **Unity / Godot**：独立引擎，透明置顶窗口支持弱（需引擎级配合），仅在"必须引擎能力"（物理/复杂特效）时选用。

> 窗口层参数（透明/无边框/置顶/不进任务栏）与 2D 完全一致，直接查 `electron.md` / `tauri.md` / `pyqt.md`。

## 3. 资产生产

- **模型格式**：glTF/GLB（推荐：体积小、内嵌骨骼动画、Web/渲染器原生支持）；FBX 需先转换。
- **来源**：用户提供（Blender 制作/素材库）或用户确认的供应商；**不要用生图工具生成 3D 模型**，此路当前不可行。
- **动画 clip**：idle / walk / jump / stretch...，命名写入 `pet.config.json` 的 `animations` 映射。
- **锚点资产**：基准模型（先确认角色模型，再调材质/绑定动画）。

```json
{
  "character": {
    "style": "3d",
    "model": "assets/pet.glb"
  },
  "animations": {
    "idle": "Idle", "jump": "Jump", "stretch": "Stretch"
  }
}
```

## 4. 渲染要点（Three.js 示例骨架）

```js
const renderer = new THREE.WebGLRenderer({ alpha: true, antialias: true }); // alpha 配合透明窗口
const loader = new THREE.GLTFLoader();
loader.load('assets/pet.glb', (gltf) => {
  scene.add(gltf.scene);
  const mixer = new THREE.AnimationMixer(gltf.scene);
  mixer.clipAction(clipByName).play();
  // 呼吸：对根节点 scale/position 做正弦微调（同 animation.md 思路）
  // 方向：拖拽方向 → 模型 yaw 旋转（8 方向=45° 步进）或相机转向
});
```

- 透明窗口 + WebGL：`alpha: true`；若黑底 → 检查 GPU 硬件加速（见 `electron-pitfalls.md`）。
- 动画切换用 `crossfade`（mixer 交叉淡入淡出），避免跳帧。

## 5. 常见坑

| 问题 | 解法 |
|---|---|
| 透明窗口渲染黑底 | `alpha:true` + 硬件加速；远程桌面/虚拟机可能失效，降级不透明背景 |
| 动画切换跳变 | clip 之间 crossfade |
| 人物大小跳变 | 加载后按包围盒统一缩放（不要手调 scaleMap） |
| 模型文件过大 | 简化网格/压缩纹理；桌面端可接受但首启加载优化 |
| 误用图像生成"3D 素材" | 3D 模型必须真实建模/导入，生图工具只用于 2D 参考图 |
