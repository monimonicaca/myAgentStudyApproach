## 1. 目的

本 skill 用于优化 BMAD 生成的 UX 文档，使最终的应用页面符合 WriteSelf 设计标准。它**不是**设计规则的副本，而是一个工作流程，指向位于本 SKILL.md 同目录下的权威规则文件（`d:\myAgentStudyApproach\skills\writeself_app_style_rules\`）。每当做出设计决策时，请 Read 拥有该决策的规则文件——切勿依赖本文档中的任何摘要。

## 2. 范围

适用于所有 WriteSelf 应用页面，包括：

- 认证 / 单任务屏幕：启动页、验证码页、忘记密码页
- 主应用屏幕：首页、日记详情、情绪追踪、AI 洞察、分析、个人资料、设置
- 上述页面中使用的所有共享 UI 组件

## 3. 规则文件参考

这些文件位于本 SKILL.md 的同目录下。在优化过程中直接 Read 它们；不要将其内容复制到此处。

| 文件 | 涵盖范围 |
|------|----------|

## 4. UX 文档优化流程

按以下步骤优化 BMAD 生成的 UX 文档。使用 Read 工具读取规则文件——不要依赖记忆或摘要。五个规则文件相互独立且篇幅紧凑；你可以在第 1 步之前先全部 Read 一次，然后将下文每步中的引用视为验证清单。

1. **识别页面类型。** Read `page_composing_rules.md`（§0"布局范围与模式"）。仅当页面出现在 Mode A 列表中（启动页、验证码页、忘记密码页）时才为 Mode A；其余均为 Mode B。如果源文档错误分类了页面，先记录修正——该分类决定了后续每步适用的章节。

2. **验证整体视觉标识。** 确认页面符合产品个性与视觉风格。Read `rules.md`（§1 视觉标识、§2 视觉风格、§7 设计原则）。

3. **检查布局与组成。** 验证结构组成——列数、每屏卡片数、对齐、内容宽度、留白和纵向流。Read `page_composing_rules.md`：Mode A 参见 §14（认证 / 单任务屏幕布局）；Mode B 参见 §1（纵向呼吸流）、§2（岛屿卡片组合）、§3（卡片尺寸系统）、§4（留白原则）、§5（单一视觉焦点规则）、§7（对齐规则）、§8（页头组合规则）、§10（数据可视化组成）、§11（滚动结构）。同时 Read `shared_page_composition_rules.md` 了解跨页面间距标准（24dp 屏幕水平内边距；16dp 卡片间距和内部内边距）。

4. **检查色彩使用。** 验证背景、品牌色/强调色/语义色、渐变和情感映射是否符合设计。Read `color_rules.md`（所有章节）。特别关注 §1.6（On Primary 文本色默认为 `#252332`，仅按下时为 `#FFFFFF`；Error 为 `#B3261A`）以及 §3（情感-色彩映射），尤其在页面可视化情绪或情感数据时。

5. **检查字体排版。** 确认字体大小、字重和层级。Read `rules.md`（§3 字体系统）。

6. **检查组件。** 对每个卡片、按钮、文本框和进度指示器，验证形状、尺寸、内边距和状态行为。Read `components_styles.md`（相关组件章节）。需显式验证的常见遗漏：卡片圆角 24–28dp（hero 卡片 28–32dp）、按钮高 46dp 圆角 22dp 药丸形、进度指示器 20dp 描边 2dp。

7. **检查交互与动效。** 验证动画、过渡和加载行为。Read `rules.md`（§6 动效与交互风格）。常见遗漏：自定义滑动/缩放过渡应移除，改用 Compose Navigation 默认值；入场动画使用淡入透明度 `tween(400ms)` 并带交错延迟。

8. **检查限制项。** 确保不存在任何"必须规避"的模式，且错误/必填字段高亮正确。Read `rules.md`（§8 限制与规避）、`components_styles.md`（OutlinedTextField 错误状态——错误不得用灰色或次要文本淡化处理），以及 `page_composing_rules.md` 中的"规避"列表（§10 密集仪表盘 / 竞争指标、§11 嵌套滚动容器）和 `shared_page_composition_rules.md`（规避密集仪表盘式布局）。

9. **输出。** 产出两份产物。第一，违规摘要，列出发现的每项违规及其在源文档中的位置和规则来源（文件 + 章节）。第二，修正后的 UX 文档。在应用了某条规则处，以内联方式引用为 `[Source: <file> §<section>]`，使每处变更均可追溯到其权威来源。

## 5. 设计清单

生成页面时，将每项对照所引用的规则文件进行检查。

- 页面是否分类到了正确的布局模式（Mode A 还是 Mode B）？ — `page_composing_rules.md` §0
- 是否尊重了产品个性和视觉风格？ — `rules.md` §1–§2
- 布局是否遵循纵向呼吸流并具有一个主导焦点？ — `page_composing_rules.md` §1、§5
- 留白是否充足且符合间距标准？ — `shared_page_composition_rules.md`
- 卡片是否为浮动式、圆角且尺寸符合当前模式？ — `page_composing_rules.md` §2–§3、`components_styles.md`
- 色彩（背景、品牌色、强调色、语义色、渐变、情感映射）是否正确？ — `color_rules.md`
- 字体排版是否匹配扁平层级和指定的字号/字重？ — `rules.md` §3
- 按钮和文本框是否遵循组件规格（形状、高度、状态）？ — `components_styles.md`
- 错误和必填字段遗漏是否被醒目高亮？ — `rules.md` §8、`components_styles.md`
- "必须规避"的模式（多列、密集、硬阴影、尖角）是否不存在？ — `rules.md` §8
- 是否恰好只有一个可滚动列且无嵌套滚动容器？ — `page_composing_rules.md` §11
- 数据可视化是否为单一居中的情感元素（感受优先，数据其次）而非密集图表？ — `page_composing_rules.md` §10
- 页头操作是否精简且为次要，无竞争按钮？ — `page_composing_rules.md` §8
- 按钮文本是否使用 On Primary 色彩（默认 `#252332`，按下 `#FFFFFF`）？ — `color_rules.md` §1.6

## 6. 常见违规示例与修正

### 示例 1 — 应用了错误的布局模式
- **违规：** 认证屏幕（如忘记密码页）被生成为多卡片加双列功能行。
- **修正：** 收缩为单张居中卡片，最大宽度 400dp，所有内容居中。
- **规则来源：** `page_composing_rules.md` §0、§14（Mode A）。

### 示例 2 — 卡片有硬边框和尖角
- **违规：** 卡片以可见的粗边框和尖锐矩形角渲染。
- **修正：** 使用圆角，无粗边框；仅依靠色调差异区分。
- **规则来源：** `components_styles.md`（Card Components）、`rules.md` §8。

### 示例 3 — 使用纯色块而非柔和渐变
- **违规：** AI 洞察卡片或主按钮被渲染为纯色块。
- **修正：** 为该元素应用定义好的柔和渐变。
- **规则来源：** `color_rules.md` §2（Gradient System）。

### 示例 4 — 错误状态被灰色/次要文本淡化
- **违规：** 空的必填字段以灰色边框和次要文本辅助文字高亮。
- **修正：** 将边框加粗至 2dp 并使用错误色，将标签/占位符变红，并显示具体的缺失原因。
- **规则来源：** `components_styles.md`（OutlinedTextField error state）、`rules.md` §8。

### 示例 5 — Mode B 页面上的仪表盘反模式
- **违规：** 等宽双列仪表盘网格，多个等重指标卡片争夺注意力，页头挤满操作按钮。
- **修正：** 单主列配 35–65% 屏高的 hero 焦点，Primary/Secondary/Supporting 卡片层级，精简次要页头操作。
- **规则来源：** `page_composing_rules.md` §1、§2、§3、§5、§8。

### 示例 6 — 情感数据使用密集分析图表
- **违规：** 情绪数据被渲染为密集的多系列图表，色彩饱和，带网格线和轴标签。
- **修正：** 替换为单一居中的情感可视化（一个关键数字 + 标签），使用柔和的情感色彩调色板。
- **规则来源：** `page_composing_rules.md` §10、`color_rules.md` §3。

### 示例 7 — 超大粗体标题破坏扁平层级
- **违规：** 屏幕标题为 24–32sp Bold，带多级标题层级。
- **修正：** 扁平化为 20sp Normal 用于页面/卡片标题，16sp 正文，14sp 按钮标签，11sp 说明文字。
- **规则来源：** `rules.md` §3。
